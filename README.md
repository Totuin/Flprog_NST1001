# Flprog_NST1001 — версия 1.0.1

Библиотека подсчёта импульсов датчика температуры NOVOSENSE NST1001.

## Подключение

```cpp
#include <flprogNST1001.h>
FLProgNST1001 sensor(2); // GPIO2, встроенная подтяжка
void nstInterrupt() { sensor.interrupt(); }
void setup() {
  attachInterrupt(sensor.interruptNumber(), nstInterrupt, FALLING);
}
void loop() {
  if (sensor.getRAW() != 0) {
    const float temperatureC = sensor.getTemperature();
  }
}
```

Ориентируйтесь на `examples/readTemperature/readTemperature.ino` — там полноценный пример с Serial.

`extPower=true` в конструкторе выбирает `INPUT` (внешняя подтяжка), а `false` — `INPUT_PULLUP`. Конкретная схема питания и подтяжки зависит от применения датчика и платы. Проверяйте допустимые уровни GPIO.

## API (публичные имена сохранены)

- `FLProgNST1001(int16_t pin, bool extPower = false)` — конфигурация входа.
- `interruptNumber()` — номер прерывания для `attachInterrupt()`.
- `interrupt()` — учёт одного импульса датчика; вызывается из обработчика прерывания на FALLING.
- `getRAW()` — число импульсов **предыдущей завершённой** серии; до получения кадра равно 0.
- `getTemperature()` — расчёт температуры в °C по числу импульсов; **при RAW = 0 значение невалидно**.

## Как работает счётчик

NST1001 кодирует температуру числом импульсов (1..3201). Между измерениями идёт пауза, по которой библиотека определяет границу серии. При первом импульсе следующей серии законченный счёт публикуется в `getRAW()`. Поэтому показание задержано на один цикл датчика.

По данным NOVOSENSE: одна серия может содержать до 3201 импульса, период импульса 5–11 мкс, а полный период измерения 32–70 мс. Указанные значения важны для оценки нагрузки прерываний на контроллер. На **AVR 8/16 МГц** программный подсчёт каждого короткого импульса может оказаться недостоверным; если чтение неточное, следует использовать аппаратный счётчик/захват импульсов или подходящий МК. Обычная компиляция не доказывает правильность счёта в реальном времени.

На 8-битных AVR `getRAW()` читает 16-битное значение с восстановлением предшествующего состояния прерываний. На 32-битных поддерживаемых платформах используется выровненное чтение `volatile uint16_t`. Если вызовы и ISR распределены между ядрами/потоками, нужна отдельная платформенная проверка синхронизации.

## Температура

Формула из datasheet (оставлена исходной):

```
Temp = RAW * 0.0625 - 50.0625
T = Temp + (Temp - 30) * 0.005,  если RAW < 1281
T = Temp,                         если 1281 <= RAW <= 2401
T = Temp + (100 - Temp) * 0.012, если RAW > 2401
```

При RAW > 3201 показание за пределами спецификации: проверьте качество сигнала и пропущенные/лишние прерывания. Библиотека не маскирует такие значения искусственным ограничением: генератор FLProg при необходимости должен контролировать допустимый диапазон.

## Зависимости и ограничения

Исходные включения `flprogUtilites.h` и `RT_HW_BASE.h` сохранены ради совместимости; **сторонние драйверы не изменялись**. Параметр `filterOrder` в исходном классе был неиспользуемым и оставлен для совместимости с наследниками; фильтрация температуры здесь не реализована.

Для испытания следует проверить датчик на реальной плате минимум при двух температурах, сравнить фактический счёт импульсов с осциллографом/аппаратным счётчиком, убедиться в отсутствии пропусков прерываний при высокой загрузке основного цикла.
